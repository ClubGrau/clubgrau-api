# Session Tokens die via sessionVersion, not passwordChangedAt

[ADR 0004](./0004-reset-invalidates-existing-sessions.md) requires previously issued JWTs to fail after complete. Comparing JWT `iat` to a `passwordChangedAt` timestamp rejects a legitimate Login in the same UNIX second as complete — the happy path is complete → “Voltar para o login” → `POST /auth`. An integer `sessionVersion` on the Employee document (Mongoose `default: 0`) is embedded in the Session Token at Login. Complete `$inc`s it. Middleware loads the authenticatable by id and refuses a claim mismatch (`401`). Claim absent is `0`, so tokens issued before this feature stay valid until a reset. The employees **entity** does not gain the field: only the schema and auth adapters read or increment it. Deactivate / Remove still do not increment (lifecycle sibling).
